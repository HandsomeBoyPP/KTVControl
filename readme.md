# KTV Control（单店 KTV 前台管理系统）

一个面向**单店 KTV**的本地前台管理系统，基于 FastAPI、SQLite 和原生 HTML/CSS/JavaScript 构建。

系统以“房态 → 开台 → 消费 → 保存账单 → 结账 → 经营记录”为主流程，适合单门店前台、收银和店长在局域网内使用。当前不设计多门店、复杂角色权限和混合支付；管理功能与敏感记录查看使用两套独立密码。

## 当前功能

### 房间与预订

- 查看全部房间及设备通电状态
- 开台、关台、续时和倒计时显示
- 同一房间存在未结账账单时禁止重复开台
- 简单预订及到时自动开台
- 设备指令持久化、失败记录和重试

### 会员

- 新增会员，编辑姓名和手机号
- 会员充值、余额支付、密码验证与密码重置
- 会员结账后保存付款会员姓名、手机号和结账后余额
- 操作日志记录会员充值、消费前后余额
- 会员统一称为“会员”，不区分普通会员、等级或会员价

### 收银台与结账

- 查看当前未结账账单和消费明细
- 选择套餐、酒水、小吃、折扣和支付方式
- 点击“保存”可保存当前账单草稿，之后继续编辑；保存不会结账、扣除会员余额或关闭房间
- 支持现金、微信、支付宝、美团和会员余额单一方式支付
- 暂不支持混合支付
- 结账只完成账务，**不会自动关台**；需要在房间管理中手动关台
- 结账记录保留套餐、商品、折扣、支付方式及付款会员快照

### 管理

- 套餐管理：每个套餐只保留一个零售价
- 库存管理：维护分类、售价、成本、库存量
- 店内人员管理：维护姓名、手机号、岗位、状态、工资和备注；人员资料不作为登录账号
- 操作日志：记录关键业务操作和敏感数据变更
- 营业报表：按营业日汇总结账、充卡、实际入账和支付方式

### 管理员模式与敏感信息

当前不做复杂账号权限，使用两套独立密码控制敏感功能：

1. 按 `Ctrl+/` 打开管理员验证。
2. 输入管理密码后，显示会员余额修改、库存成本、人员工资以及删除按钮。
3. 再按 `Ctrl+/` 可退出管理员模式并重新隐藏敏感内容。
4. 手动修改库存数量时，无论管理员模式是否已打开，都需要再次输入管理密码确认。

5. 营业报表、充卡记录和操作日志默认隐藏，按 `Ctrl+\` 输入记录查看密码后统一显示，再按一次重新隐藏。

> 默认管理密码为 `admin123`，默认记录查看密码为 `records123`。两项都保存在 `data/config.json`，正式使用前请分别修改。

## 关键业务规则

- 单店、单套数据；管理操作和记录查看使用两套独立密码。
- 套餐只有一个零售价，不区分会员价和非会员价。
- 金额当前使用浮点数保存和计算，适合现阶段使用；正式长期运营前建议改为“分”为单位的整数金额。
- 一笔账单只能选择一种支付方式。
- 保存账单草稿不等于结账。
- 结账后账单关闭，但房间继续保持开台状态。
- 酒水和小吃加入账单后会同步扣减库存。
- 会员余额支付需要验证会员密码并校验余额。

## 技术栈

| 层面 | 技术 |
| --- | --- |
| 后端 | Python、FastAPI、Uvicorn |
| 数据库 | SQLite（WAL 模式） |
| 前端 | 原生 HTML、CSS、JavaScript，单页应用 |
| 硬件对接 | KTV 房间设备 HTTP API |

## 项目结构

```text
KTVControl/
├─ main.py            # FastAPI 应用和 API 路由
├─ models.py          # Pydantic 请求模型
├─ database.py        # SQLite 初始化、迁移和操作日志
├─ scheduler.py       # 设备指令、失败重试、定时任务和预订调度
├─ state_manager.py   # 预订、定时状态和房间 IP 缓存
├─ requirements.txt   # Python 依赖
├─ data/              # 运行数据：数据库和本地配置
└─ static/
   ├─ index.html      # 前端页面
   ├─ app.js          # 前端业务逻辑
   └─ style.css       # 页面样式
```

## 快速开始

### 1. 创建并激活虚拟环境（推荐）

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. 安装依赖

```powershell
pip install -r requirements.txt
```

### 3. 启动服务

```powershell
uvicorn main:app --host 0.0.0.0 --port 8000
```

### 4. 打开系统

本机访问：<http://localhost:8000>

同一局域网内的其他设备可通过运行电脑的局域网 IP 加端口访问，例如 `http://192.168.1.10:8000`。

## 配置与数据

### 硬件接口

KTV 硬件 API 地址在 `scheduler.py` 中配置：

```python
KTV_API_BASE = "http://192.168.110.201:18888"
```

### 本地数据

- `data/ktv.db`：SQLite 业务数据库
- `data/config.json`：本地配置、管理密码和记录查看密码
- `data/room_ip_map.json`：房间与设备 IP 映射缓存

`data/` 属于门店运行数据。上传 GitHub 前应确认 `.gitignore` 已排除真实数据库、密码配置、备份文件和顾客信息；仓库中只保留脱敏示例配置。

## 主要 API

| 模块 | 方法与路径 | 说明 |
| --- | --- | --- |
| 房间 | `GET /api/rooms`、`GET /api/rooms/status` | 房间列表和设备状态 |
| 房间 | `POST /api/rooms/open`、`POST /api/rooms/close`、`POST /api/rooms/extend` | 开台、关台和续时 |
| 预订 | `GET/POST /api/bookings`、`DELETE /api/bookings/{id}` | 预订管理 |
| 会员 | `GET/POST /api/members`、`PUT /api/members/{id}` | 会员查询、新增和编辑 |
| 会员 | `POST /api/members/verify`、`POST /api/members/{id}/recharge` | 密码验证和充值 |
| 会员 | `POST /api/members/{id}/reset-password` | 重置会员密码 |
| 套餐 | `GET/POST /api/packages`、`PUT/DELETE /api/packages/{id}` | 套餐管理 |
| 库存 | `GET/POST /api/inventory`、`PUT/DELETE /api/inventory/{id}` | 商品和库存管理 |
| 人员 | `GET/POST /api/staff`、`PUT/DELETE /api/staff/{id}` | 店内人员管理 |
| 账单 | `GET /api/billing/active` | 当前未结账账单 |
| 账单 | `PUT /api/billing/{id}/draft` | 保存结账页面草稿 |
| 账单 | `PUT /api/billing/{id}` | 编辑未结账账单 |
| 账单 | `POST /api/billing/add-drink`、`DELETE /api/billing/drink/{id}` | 消费明细管理 |
| 账单 | `POST /api/billing/settle`、`GET /api/billing/history` | 结账和结账记录 |
| 账单 | `DELETE /api/billing/{id}` | 删除账单（当前实现，后续计划改为作废/冲正） |
| 管理 | `POST /api/admin/verify`、`POST /api/records/verify` | 管理密码和记录查看密码验证 |
| 记录 | `GET /api/reports/daily`、`GET /api/recharge-logs`、`GET /api/operation-logs` | 受记录查看密码保护的敏感记录 |

## 主要数据表

| 表名 | 用途 |
| --- | --- |
| `members` | 会员姓名、手机号、密码和余额 |
| `recharge_logs` | 会员充值记录 |
| `packages` | 套餐名称、时长和零售价 |
| `inventory` | 商品分类、售价、成本和库存 |
| `billing_records` | 房间账单、草稿、金额、支付和会员快照 |
| `drink_orders` | 酒水和小吃消费明细 |
| `bookings` | 包厢预订 |
| `staff` | 店内人员资料和工资 |
| `operation_logs` | 操作审计日志 |
| `auto_close_schedules` | 定时任务 |
| `device_commands` | 设备指令、执行状态和错误信息 |

数据库会在启动时自动创建和迁移。预订、定时任务和设备指令均保存在 SQLite 中，避免服务重启后完全丢失状态。

## 后续功能规划（单店场景）

本项目优先把单店日常营业闭环做稳定，不按连锁门店或大型 SaaS 的方向扩张。

### P0：稳定日常营业

- **营业报表与交班**：实现营业日报、周报、月报、年报；按支付方式汇总房费、商品销售、会员充值、优惠、成本和毛利，列出未结账账单，并支持交班确认和 CSV/Excel 导出。
- **库存流水与盘点**：记录采购入库、销售出库、退回和人工调整；支持盘点差异、低库存提醒，并记录调整原因和操作人。
- **预订闭环**：补充顾客姓名、手机号和备注；校验同一包厢时段冲突；增加待到店、已到店、取消和爽约状态。
- **账务纠错与审计**：已结账账单不再直接删除，改为作废或冲正，并保留原账单、原因、操作时间和操作人；充值、折扣和库存调整全部可追溯。
- **数据备份与恢复**：提供手动备份、每日自动备份、一键恢复和备份保留策略，并在恢复前自动生成安全副本。
- **异常自检**：检查房态与未结账账单是否一致、是否存在重复开台账单、库存是否出现异常负数，并提供安全修复入口。

### P1：提高前台和店长效率

- **经营看板**：展示今日营业额、房间利用率、平均消费、会员充值、畅销套餐、畅销商品和低库存提醒。
- **小票与单据**：支持结账小票、会员充值凭证和交班单打印，可选接入热敏打印机和钱箱。
- **会员账本**：查询每位会员的充值、消费和余额变动明细；余额调整必须填写原因并保留审计记录。
- **套餐时段**：支持套餐启停和适用时段，继续保持单一零售价，不引入会员等级、多套价格和复杂营销引擎。
- **当班人员记录**：把开台、优惠、结账、作废和库存调整关联到当班员工，仅用于业务追溯，不建立复杂角色权限。
- **设备状态中心**：集中显示房间设备离线、指令失败、重试次数和最后响应时间。

### P2：按实际经营需要增强

- **包厢运营状态**：增加待清洁、清洁中、可开台和设备故障状态。
- **商品管理增强**：增加供应商、采购价历史、条码快速录入和临期提醒。
- **顾客提醒**：增加预订到店提醒、即将到时提醒和会员生日提醒；短信或其他通知渠道按需接入。
- **移动端适配**：优化手机和平板操作，方便服务员在店内局域网使用。
- **历史数据归档**：按月归档历史账单和操作日志，保持本地数据库长期运行稳定。

## 暂不纳入范围

为避免单店系统过度复杂，现阶段不计划实现：

- 多门店切换、总部管理、跨店会员、跨店库存和云端多租户
- 多层级 RBAC、审批流、单点登录和复杂账号权限
- 一笔订单拆分为现金、微信、支付宝和会员余额的混合支付
- 积分商城、复杂优惠券平台、团购渠道自动核销
- 完整会计、开票、ERP、供应链和微服务架构

## 推荐实施顺序

1. 营业报表、交班和数据导出。
2. 数据备份恢复、账单冲正和异常自检。
3. 库存流水、盘点和低库存提醒。
4. 预订闭环、会员账本和经营看板。
5. 小票打印、设备状态中心及移动端优化。

这套顺序先解决“每天账能不能对上、数据能不能找回、库存是否准确”三个单店最关键的问题，再逐步提升前台效率和顾客体验。
